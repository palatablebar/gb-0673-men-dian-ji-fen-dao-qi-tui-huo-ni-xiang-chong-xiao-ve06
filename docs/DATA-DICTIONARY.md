# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。

# 规则迁移（M8）

迁移只处理切换后的影响，不重写切换前历史。切换时点 `migration.cutover_at` 默认2026-12-01T00:00:00+08:00，目标规则版本 `migration.target_version` 默认2026.12.1-r1，统一有效期 `migration.validity_days` 默认45天，新到期=原发放时刻+有效期（半开区间，到期时刻立即不可用）。迁移基准是旧规则重放到切换时点后的在切余额，切换前已自然到期的批次余额为零，不产生迁移差异。

差异去向码：`EARLY_EXPIRY`（新到期不晚于切换时点，提前到期作废，未保留）、`RESCHEDULED`（保留余额并重定到期，含缩短与延期）、`UNCHANGED`（新旧到期一致，原样保留）。守恒式：旧版在切余额=新版保留(`kept_total`)+未保留差异(`dropped_total`)，并按会员逐户核验。总量或会员级不平衡、或基线行守恒/积分守恒/退货核验不通过时，`eligible=false`、状态 `BLOCKED`，发布被拒并保留旧版余额。

新版批次字段：`id` 为 `原批次号@目标版本`，`source_lot`/`source_event` 指向原批次与原发放事件，`issued_at` 保留原发放时刻，`rule_version` 标记目标版本，`at` 为切换时点，`remaining=issued=迁移金额`。发布状态持久化在 runs 表 `migration_status`（未发布/已发布），发布幂等，重复发布不重复计入；迁移证据写入归档包 `migration.json`。样例数据集 `migration`：切换时点旧版在切400，新版保留220，提前到期未保留180，守恒可复核。
